# UNIFORMITY

**The OS composes. The domains remain real.**

</div>

---

Uniformity is the operating system and composition layer behind a portfolio of deliberately distinct products. It standardises **identity, canonical object state, permissions, evidence, action, verification and history** — without collapsing every domain into one application.

```text
Object → State → Signal → Evidence → Intelligence → Action → Verification → History
```

### The product model

| | Surface | Owns | Must never own |
| :--- | :--- | :--- | :--- |
| ⬡ | **uniformity-os** — the OS | identity, canonical object/state, permissions, events, orchestration, role/context | instrument semantics, advisory reasoning |
| ⬢ | **SUBANGEL** — one instrument world | instrument & workshop semantics with LOGARHYTHM | cross-domain OS truth |
| ⬡ | **resell-chief** — RESELL | resale and transaction truth | instrument-domain truth |
| ⬢ | **uniformity-engineering-link** | engineering handoff contracts and CI validation | product-domain truth |
| ⬡ | **JUNO-106** — reference object | proving the runtime | being a product |
| ⬢ | **Fridge Brain** — advisory service | interpretation, provenance, one proposed next action | canonical state mutation |

### Role projections

**Matt** (technical) · **Susanna** (operational) · **Customer** (safe status) · **Logarhythm** (public) — all resolve the **same canonical `object_id`**.

### Boundaries, enforced not documented

- **Fridge Brain may propose; it may never mutate.** Evidence is filtered before it crosses the service boundary.
- **A completed action** appends verified evidence and updates canonical state **exactly once**.
- **History is immutable.** Records are superseded, never erased.
- **Staging is not verification.**
